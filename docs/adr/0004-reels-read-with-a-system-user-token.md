# The reels sync reads Instagram with a system-user token

Ticket E built the reels sync on the Instagram API with Instagram Login: a 60-day `IGAA…` token on `graph.instagram.com`, extended by every run. When Josip set up the Meta app (2026-11-10), the dashboard offered new apps only "API setup with Unified login" (business portfolio required) and "with Facebook login"; adding voxford.official as an "Instagram Tester" failed with "Invalid id". So the sync now uses a system-user token of the business portfolio that owns voxford.official (`EAA…`, `instagram_basic`, expiration "Never") on `graph.facebook.com/{ig-user-id}/media`; the account is the one Instagram account assigned to that system user (`me/assigned_instagram_accounts`), or the optional secret `INSTAGRAM_USER_ID` when set. The token never expires, so the daily refresh is gone; a revoked token shows as code 190 in the Worker log and `scripts/instagram-wizard.sh token` replaces it.

Considered: Facebook login (needs a Facebook Page linked to the account and a user token that expires) and the Unified login redirect flow (needs a callback URL and an app-secret exchange). A system user made in Business settings needs neither, and the app stays in Development mode: it reads only its own portfolio's account, so no business verification or App Review.
