# The reels sync reads Instagram with a system-user token

Ticket E built the reels sync on the Instagram API with Instagram Login: a 60-day `IGAA…` token on `graph.instagram.com`, extended by every run. When Josip set up the Meta app (2026-11-10), the dashboard offered new apps only "API setup with Unified login" (business portfolio required) and "with Facebook login"; adding voxford.official as an "Instagram Tester" failed with "Invalid id". So the sync now uses a system-user token of the business portfolio that owns voxford.official (`EAA…`, `instagram_basic`, expiration "Never") on `graph.facebook.com/{ig-user-id}/media`. The system user is assigned the Voxford Facebook Page, which voxford.official is linked to: assigning the Instagram account itself in Business settings needs an Instagram login there that failed ("Something went wrong"), and Meta's Instagram media reference documents the Page route. The token therefore carries `instagram_basic`, `pages_show_list` and `pages_read_engagement`, all read-only. The Worker finds the account through the Page (`me/accounts?fields=instagram_business_account`), else among Instagram accounts assigned directly (`me/assigned_instagram_accounts`); the optional secret `INSTAGRAM_USER_ID` overrides both. The token never expires, so the daily refresh is gone; a revoked token shows as code 190 in the Worker log and `scripts/instagram-wizard.sh token` replaces it.

Considered: Facebook login (needs a Facebook Page linked to the account and a user token that expires) and the Unified login redirect flow (needs a callback URL and an app-secret exchange). A system user made in Business settings needs neither, and the app stays in Development mode: it reads only its own portfolio's account, so no business verification or App Review.
